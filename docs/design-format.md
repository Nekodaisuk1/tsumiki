# Tsumiki Design v5

## Purpose
`.tsumiki.json` は、画面キャプチャではなく設計と解析入力そのものを持ち運ぶ専用様式。UTF-8のJSONを使用し、特定のブラウザ保存領域や外部URLに依存せず復元する。

- [JSON Schema](../public/schemas/tsumiki-design-v5.schema.json)
- [Example design](../public/examples/box-frame.tsumiki.json)
- 実装上の最終検証: `src/structure/design.ts` の `validateDesign`。

## Header

```json
{
  "format": "tsumiki-design",
  "version": 5,
  "solver": "frame3d-contact-v5",
  "units": "dimensionless",
  "jointModel": "clearance-contact",
  "joint": { "contactStiffness": 2000, "openStiffness": 0.5 },
  "ropeWrap": "locked"
}
```

これはヘッダ部分の抜粋。完全なファイルには以下の全項目が必要。既定値を黙って補わず、未知のバージョン・解析モデル・未対応の項目は拒否する。

## Contents

| Field | Meaning |
| --- | --- |
| name, notes | 設計名、仮定や観察の記録 |
| jointModel | `clearance-contact`（穴と角棒の隙間・接触）または `rigid-approximation`（剛接合近似） |
| joint | contactStiffness（接触時の相対剛性）、openStiffness（隙間内の小さな抵抗）。openStiffness < contactStiffness |
| ropeWrap | 掛け点C・Bの摩擦の両極端。`sliding`（滑る・張力一様）または `locked`（巻き取り後に滑らない） |
| nodes | ID、右手系XYZ座標、6自由度すべてを固定するか。Yが鉛直上向き |
| members | 雄材・雌材、始点と終点、材料ID、roll（板の回転角）、layer（雌材の重ね段）、holeCount（穴数）。節点を共有する部材は剛接合近似 |
| materials | E、G、A、Iy、Iz、J、density。実物の規格ではない無次元仮定値 |
| ropes | 4接触点の順序 A,C,B,D、相対軸剛性、巻き取り後の張力ひずみ、たるみ比率、巻き取り雄材のID |
| rings | member（取付先の雄材）、end（start/endの角棒）、slot（段）、`spacer-unmodeled`。空隙を埋める位置を保存するが接触・質量・剛性の寄与は未解析 |
| connections | 雄材・雌材のID、雄材の端、穴番号、シャフト上の段。解析時に雌材を穴で分割し構造接続を拘束 |
| geometry | boardWidth、thickness、tenonSize、tenonLength、holeSize。規格確定前の無次元の形状仮定 |
| analysis | 荷重点、XYZ方向、外力・同軸モーメント、自重係数、床加速度、周波数、時間、加振停止時刻、減衰、時間刻み |
| view | 変形の表示倍率。カメラ位置は解析条件に含めない |

IDは全配列を通じて一意。部材・ロープ・丸材・荷重点の参照先が存在することを検証する。部材はゼロ長と同一の節点・段の重複を拒否。異なる段の雌材は同じ節点間へ重ねられる。ロープの開始・終端と、中間の隣接2点が、それぞれ雄材の両端であることも検証する。JSON Schemaでは表せない参照・位相・条件間の制約はアプリで検証する。

節点上限32、配列上限100、ファイル上限1 MB。数値は有限値かつ各項目の許容範囲内。支持不足・荷重点固定・不安定剛性・ロープ非収束は、ファイルとして有効でも解析時にエラーになる。ファイルの有効性は、実物の穴の適合・組立可能性・安全性を意味しない。

## Reproduction contract
同じsolverバージョン・同じ入力と要素順序で同じ計算を実行する。入力順序も保存し、丸めた表示値から再構築しない。乱数や実際のフレームレートは解析に用いず、`timeStep` に従って決定的に計算する。カメラ操作や再生速度は解析値を変更しない。

画面では、座標・部材・支持・ロープ経路・材料・解析条件を編集できる。設計はファイルで明示的に保存する。変更はブラウザの下書きにも保存する。「下書きを復元」で明示的に戻せる。端末間での持ち運びや長期保存にはファイルを使用する。

異なる実行環境での浮動小数点結果のビット一致までは保証しない。解析モデル変更時はsolver識別子を更新し、形式変更時はversionを更新する。自動変換がないバージョンは読み込まない。

## Analysis report
`analysis.tsumiki-report.json` は、完全な設計と、各ロープ条件の静的変位・反力・部材端内力・張力、加振入力・荷重点変位時系列・ピーク値・ロープ切替警告を保存する。設計ファイルは再計算の入力、レポートはその実行結果として区別する。

## Future extensions
実寸単位、実規格との対応と差し込み検証、接合の遊び・摩擦・抜け止め、ロープ巻き取り・保持、丸材の力学的役割は、仕様が固まった時点で明示的な形式拡張として扱う。現行v4にあると見なさない。

## Geometry and spacer seats
雄材は長手方向の両端に角棒を持つ。雌材は両端の接続位置を含めたholeCount個の角穴を等間隔で配置し、板厚方向に貫通させる。実物の穴数・ピッチは未確定で、ここでの値は再現可能な描画仮定。穴の重なりと、角棒が穴を通らない寸法関係を拒否する。

丸材は雄材の始点側または終点側の角棒に沿って取り付ける。slot=0は肩に最も近い段。雌材layerと丸材slotは同じ板厚単位で重ねる。雌材が0段と2段にある例では、丸材で1段の空隙を埋める。重複・雌材と同じ段・角棒より外側への丸材配置を拒否する。形状の積層表示と、梁中心線による解析の接続位置は区別する。偏心、接触・隙間・摩擦、穴による断面欠損を自動で力学モデルへ反映するものではない。

## Version 1 migration
v1のJSON Schemaは履歴として残す。v1は専用の明示的変換でv2へ読み込める。部材にはroll=0、layer=0、holeCount=7、共通形状の仮値を付与し、旧丸材の節点に接続する雄材を探して始点/終点側の1段へ変換する。対応する雄材がない場合や重複が生じる場合はエラーにし、丸材を勝手に削除しない。

読み込み画面に移行した旨を表示する。旧構造の座標・荷重は保持するが、穴数や丸材取付は新しく付与した仮定なので利用者が確認する。solver v2はrollによる断面軸の回転に対応し、v1のroll=0での局所軸の規則を保持する。再保存はv2を出力する。

## Version 5
v5は接合モデルの選択、接合パラメータ、掛け点の摩擦の仮定を追加した。v4以前のファイルは、結果を再現するため `rigid-approximation`・`sliding` で読み込む。新規の設計は `clearance-contact`・`locked` を既定とする。v5の `prestrain` は巻き取り後の張力（[Prototype 05](joint-clearance.md)）。剛接合の静的な荷重増分（比較表の値）と動的応答は、v4と同じ値になる。張力ありでは、初期張力を含む全変位と張力が巻き取り後の定義の分だけv4と異なる。

## Current v4 rules

[穴スナップと最外側ロープの仕様](hole-snap-and-rope.md)が現在の動作を定義する。凸部長は必ず板厚×5、部材・丸材は0〜3段、先端1枚分はロープ用。新しい雌材（手動追加・テンプレート）は、両端の角棒で空いていて干渉しない最も内側の段へ追加する。2節点間に張る雌材（筋交い）は角棒に垂直な面内に限り、図面規格では節点間距離が雌材の穴中心間距離と一致する規格を使う。交差する筋交いは干渉判定により別の段へ入る。規格ごとの伸縮は同じ端形状（角・丸）の隣の規格へ替え、他の部材と共有する端を残して反対の端を動かす。移動ツール（G）は既定で接続を保つ。動かす部分と外側の雄材との接続（角棒に載った板、記録された穴接続）がすべて1本の角棒の軸上にあれば、その軸まわりの回転だけを許し、15mm刻みの掃引で干渉する手前で止める。軸の異なる接続が複数あれば動かさない。C で接続を無視する自由移動に切り替える。標準設計は0・1段に詰める。

connectionsを読み込むと、参照・穴番号・垂直性・板厚段・シャフトが通過する全ての雌材との一致を検証する。接続を黙って追加・削除しない。solver v4は穴で分割した梁と剛オフセット、最外側に掛かるロープを扱う。旧バージョンの解析値と完全一致するとはしない。

v2は長さ比を5枚分へ移行し、v3はconnectionsを空配列として追加する。旧版は接続情報を持たないため、中間穴にあるように見えるだけの既存部材を勝手に接続しない。移行を表示し、利用者が設計と結果を確認する。


## Drawing geometry v6

図面規格は `version: 6` とし、geometryに `specification: "hitoto-v1"` と `tenonCornerRadius`、全memberに `catalogId` を必須とする。幾何座標1単位=1000mm。unitsは解析の相対量を維持するためdimensionlessのまま。solverも既存の相対フレームモデルで、丸穴の接触則は未対応。v5は自動実寸化せず保持する。詳細は[実験009](experiments/009-hitoto-drawing.md)、スキーマは[design v6](../public/schemas/tsumiki-design-v6.schema.json)を参照。
